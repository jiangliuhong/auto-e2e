# auto-e2e compile 命令 — Markdown 用例 → Playwright spec 骨架

## 目标与范围

实现 `auto-e2e compile`,把**已校验的 Markdown 用例契约**确定性映射为 Playwright `.spec.ts` 骨架。这是上一个 PR(skill 命令核心)明确的下一步 —— 契约 schema 已钉死,compile 只是确定性模板映射。

**本 PR 范围:**
1. `compile` 命令:顶层命令 `auto-e2e compile <case.md> --out <spec.ts>`。
2. 纯函数 spec 渲染器(`case-spec.ts`):TestCaseCase → `.spec.ts` 文本(骨架 + TODO)。
3. Runtime 方法 `compile()` + CLI 编排。
4. 完整单测(纯函数优先 + tmpdir 端到端)。
5. 文档更新。

**明确不在本 PR:** `from-skill` 一条龙、`skill run`。

---

## 关键设计决策(已与你确认)

1. **产物详细度 = 骨架 + TODO**(纯确定性,不推理):
   - `route` → `page.goto(route)`(若 config.baseUrl 存在用相对路径,否则原样)。
   - 每个 `Step` → `await test.step('原文', async () => { /** TODO: 实现步骤 */ })`。
   - 每个 `Assertion` → `expect(...).toBeVisible()` 占位 + `// TODO: <原文断言>` 注释。
   - `Network Expectations` → `page.route` 拦截 + `expect(...)` 计数(确定性可做,因为契约给了方法+路径)。
   - 统一 4xx/5xx 拦截断言:若 Stability Notes 含「401/403/500」或契约类型含 `readonly`,默认加一段 `page.on('response', ...)` 检查无 4xx/5xx。
   - `storageState` 来自 config → `test.use({ storageState })`。
   - viewport 来自 config → `test.use({ viewport })`。
2. **定位 = 顶层命令**(与 generate/run 并列,compile 是通用 Markdown→spec 映射器,不强依赖 skill)。
3. **校验策略 = 先校验**(compile 前强制 `validateCaseMarkdown`,缺必填段/写操作未声明 → 拒绝编译并返回所有错误)。

## case-spec.ts 渲染规则(纯函数)

**输入:** `{ testCase: TestCaseCase; config?: Config; appMap?: AppMap; slug: string }`
**输出:** `.spec.ts` 文本字符串。

渲染结构(对齐 Playwright 标准):
```ts
import { test, expect, type Page } from '@playwright/test'

// 由 auto-e2e compile 生成。骨架基于用例契约,真实选择器需编码 Agent 补全。
// 用例契约来源:<slug>.md

test.use({ /* viewport / storageState 来自 config,有则填 */ })

test.describe('<title>', () => {
  test('<slug>', async ({ page }) => {
    // --- Network Expectations(确定性:契约给了方法+路径)---
    // page.route('**/api/...', route => ...) + expect 计数

    // --- Steps(骨架,原文进 test.step + TODO)---
    await test.step('1. 登录...', async () => {
      /** TODO: 实现该步骤 */
    })

    // --- Assertions(占位 + 原文注释)---
    // TODO: 页面标题可见
    await expect(page).toHaveTitle(/.*/)  // 占位
  })
})
```

**确定性原则:** 不从中文 Step 推断 getByRole/getByLabel;所有需要应用语义的地方留 TODO + 原文。route/goto、network 拦截、viewport/storageState 这些**契约/config 已显式给出**的部分做实。

## Runtime.compile 流程

1. `ensureLayout()`。
2. 解析 caseFile(相对 root 解析为绝对)→ 读文本;缺失报错。
3. **先校验**:`validateCaseMarkdown(markdown)`;未通过 → 返回所有错误,**不落盘**。
4. 读 scan 产物(app-map,仅用于 testDir 回退)+ config(viewport/storageState/baseUrl)。
5. 推导输出路径:`options.out` 必填(对齐你的用法 `--out xxx.spec.ts`)。若目录不存在,writeText 自动建。
6. `--force` 守门:已存在且未 force → `compile_spec_exists` 错误。
7. 渲染 `generateCaseSpec()` → 落盘。
8. 返回 `{ ok, specPath, suggestedRunCommand }`,其中 `suggestedRunCommand = 'auto-e2e run --spec <path>'`。

> 不自动触发 scan:compile 不需要路由/选择器上下文(那已写进 Markdown 用例),只需 config。避免与 generate 的 scan 副作用耦合。

## CLI 形态(对齐你的目标用法)

```bash
auto-e2e compile tests/auto-e2e-cases/pl-forecast/detail.md \
  --out tests/auto-e2e-generated/detail.spec.ts \
  [--root <path>] [--force]
```

| 选项              | 说明                                       | 默认 |
| ----------------- | ------------------------------------------ | ---- |
| `<caseFile>`      | 用例 Markdown 文件(位置参数,必填)        | —    |
| `--out <file>`    | spec 输出路径(必填,相对项目根)           | —    |
| `--root <path>`   | 项目根目录                                 | cwd  |
| `--force`         | 覆盖已存在的 spec                          | false |

输出示例:
```
✓ spec 骨架已生成:detail
spec: /abs/tests/auto-e2e-generated/detail.spec.ts
下一步: 由编码 Agent 补全 TODO(真实选择器与断言),再执行 `auto-e2e run --spec <路径>`
```

## 执行顺序

1. **渲染层**:`case-spec.ts` 纯函数 + 单测(最先稳定)。
2. **类型层**:`CompileOptions`/`CompileResult` + `AutoE2ERuntime.compile`。
3. **Runtime 层**:`default-runtime.ts` 实现 `compile()`。
4. **CLI 层**:`commands/compile.ts` + `index.ts` 注册。
5. **测试**:`cli/commands/compile.test.ts`(tmpdir 端到端)。
6. **文档**:`USAGE.md` 加 compile 章节 + 命令一览;`OUTPUT_SPEC.md` 补说明(spec 骨架是可提交资产,不在 .auto-e2e/)。
7. **验证**:typecheck + test + format:check。
