# Auto E2E Runtime Architecture

## Vision

Auto E2E is **not** an AI agent.

It is an **Agent Runtime** for browser automation.

The Runtime provides a stable, structured, and deterministic execution environment for Coding Agents such as Codex, Claude Code, Cursor, and OpenCode.

The Runtime never performs reasoning.

Reasoning is always performed by an external Agent.

The Runtime only provides:

- Environment
- Observation
- Execution
- Feedback

---

## Design Principles

### Single Responsibility

Every module should have only one responsibility.

Avoid God Objects.

Avoid modules larger than a few hundred lines.

### Repository First

Business logic must not depend on CLI.

Business logic must not depend on Playwright directly.

CLI should only orchestrate Runtime APIs.

### Runtime First

The Runtime is the center of the project.

```text
CLI
│
▼
Runtime
├── Environment
├── Scanner
├── Observer
├── Executor
├── Feedback
└── Storage
```

---

## Runtime Lifecycle

```text
Prepare Environment
        │
        ▼
Scan Project
        │
        ▼
Observe Application
        │
        ▼
Execute Test
        │
        ▼
Collect Artifacts
        │
        ▼
Generate Structured Feedback
```

No module should skip this lifecycle.

---

## Module Responsibilities

### Environment

Responsible for:

- Start project
- Stop project
- Restart project
- Wait until ready
- Health check
- Storage state
- Test fixtures

No browser logic.

### Scanner

Responsible for project discovery.

Supported frameworks:

- React
- Next.js
- Vue
- Vite

Outputs:

- app-map.json
- selector-map.json
- codex-context.md

No Playwright dependency.

### Observer

Responsible for application observation.

Produces structured information instead of screenshots only.

Should collect:

- DOM Snapshot
- Accessibility Tree
- URL
- Title
- Buttons
- Inputs
- Tables
- Links
- Dialogs
- Recommended Selectors
- Console Messages
- Network Requests
- Screenshot

The Observer never executes assertions.

### Executor

Responsible for running Playwright.

Supports:

- run
- runSpec
- runSuite
- runTag

Collects:

- Trace
- Screenshot
- Video
- HTML Report
- JSON Report

No business analysis.

### Feedback

Responsible for transforming execution results into structured data.

Outputs:

- run-result.json
- failure-summary.md

Future outputs:

- dom-diff.json
- network-summary.json

Feedback must be machine-readable.

### Storage

Responsible for Runtime persistence.

Everything generated by Runtime should be stored inside:

```text
.auto-e2e/
```

Never scatter runtime artifacts throughout the project.

---

## Provider Architecture

All implementations should be replaceable.

Examples:

BrowserProvider:

- Playwright
- Chrome, future

EnvironmentProvider:

- Local Node
- Docker, future
- Remote, future

ReportProvider:

- HTML
- JSON
- JUnit

Never hardcode provider implementations into Runtime.

## Non Goals

The Runtime should never:

- Call an LLM
- Depend on OpenAI or Anthropic
- Perform reasoning
- Modify business code
- Guess application behavior

Those responsibilities belong to external Coding Agents.
